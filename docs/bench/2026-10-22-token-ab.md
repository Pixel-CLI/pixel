# Token A/B: Pixel vs vanilla vs RTK (2026-10-22)

Measured, not estimated: provider-reported token usage from each agent's own
transcript, Pixel 0.9.0 (`5cd31f0`, binary sha256 in each receipt) against
the same agent without Pixel, on 13 public questions about ripgrep at
`3fce3b5`, 3 repetitions per arm per agent. RTK 1.0.1 is simulated on the
baseline sessions (method below), not run live.

## Result

| Agent | Vanilla tokens | With Pixel | Δ | Runs with fewer tokens | Tool calls | Answer score (blind, /3) |
|---|---:|---:|---:|---:|---:|---|
| Claude Code 2.1.307 | 7,225,441 | 4,096,721 | **−43.3%** | 11/13 questions (median) | 149 → 59 | 2.95 → 2.85 |
| Codex | 6,917,737 | 1,503,869 | **−78.3%** | 39/39 runs | 210 → 32 | 3.00 → 2.95 |

| Same baseline sessions, RTK simulated | Command output | Total tokens |
|---|---:|---:|
| Claude Code | −33.4% | **−9.0%** |
| Codex | −10.7% | **−4.7%** |

Why the gap: most of a session's tokens are the agent re-reading its own
context on every model call (Claude: 91% of baseline tokens are cache reads).
RTK makes each command's output smaller; Pixel's prompt-submit brief removes
model calls (Claude 182 → 96 over 3 reps). They stack: RTK on the commands
Pixel does not remove.

Wall time over the 39 Claude runs: 1,042 s → 788 s (−24%).
Price-weighted Claude tokens (input 1, cache write 1.25, cache read 0.1,
output 5): −23.4%. Raw token counts overstate the bill, because cache reads
are cheap.

## What this does not show

- **Question mix favours Pixel.** These are code-understanding questions.
  RTK's large wins (test runs, builds, `git diff`) do not occur in them; a
  build-and-test task set would score RTK higher.
- **RTK is simulated.** Every baseline Bash/`exec_command` call was replayed
  raw and through `rtk rewrite` in the same clone, with a fresh `HOME`
  (default RTK filters). The output saving was charged to every later model
  call that carried it. This assumes RTK changes no agent decision, which
  favours RTK.
- **Answer quality dropped slightly.** One LLM judge, blind to the arm,
  graded each answer against the source. Claude + Pixel had one material error
  in 39 answers (misread a benchmark figure in the `history` question); the
  vanilla arm had none. Codex + Pixel lost one point twice on the same
  question (`lookup`: stopped before saying where the parsed value is
  applied).
- **Codex baseline carries a plugin cost.** Both Codex arms have Codex's
  curated `superpowers` plugin; the vanilla arm read its skill files more
  (74 calls vs 19), 32% of its tool-output bytes. Excluding those reads,
  Pixel's work output is still 94% smaller (1.71 MB → 0.10 MB).
- **One repository, one machine, n=3.** The `overview` question got no brief
  in any run.
- Both Claude arms load the user's global `CLAUDE.md`; no RTK hook was
  active in either (`--setting-sources project`).

## Reproduce

```bash
S=.agents/skills/arena/arena.sh
$S run-set single --agent claude --pixel-bin "$(command -v pixel)"   # x3
$S run-set single --pixel-bin "$(command -v pixel)"                  # Codex, x3
python3 -I scripts/bench/token-ab/tokens.py <set-dir>          # per-arm token breakdown (Claude)
python3 -I scripts/bench/token-ab/rtk_replay.py <set-dir>...   # RTK simulation (Claude)
python3 -I scripts/bench/token-ab/rtk_replay_codex.py <set-dir>...
```

Every run, one row per arm (tokens, tool calls, seconds, blind grade and the
judge's errors): [`receipts/2026-10-22-token-ab.jsonl`](receipts/2026-10-22-token-ab.jsonl).
The two result tables re-derive from it:

```bash
jq -s 'group_by(.agent)[] | {agent: .[0].agent,
  vanilla: (map(select(.arm=="no-pixel").tokens.total_tokens) | add),
  pixel:   (map(select(.arm=="pixel").tokens.total_tokens) | add)}' \
  docs/bench/receipts/2026-10-22-token-ab.jsonl
```

The ripgrep clone is `BurntSushi/ripgrep` at `3fce3b5` placed at
`$CENSUS_ROOT/cache/ripgrep`. Sets used: Claude `single-20261022T003927Z`,
`T004721Z`, `T005301Z`; Codex `T010111Z`, `T010735Z`, `T011254Z`.
