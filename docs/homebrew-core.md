# Submitting pixel to homebrew-core

The tap (`brew install LivioGama/tap/pixel`) installs the release's prebuilt
binary, and Linux bottles since #465. homebrew-core accepts neither: it builds
every formula from source on its own CI and makes its own bottles. Each release
therefore also ships `pixel-core.rb`, the formula a homebrew-core pull request
carries, generated by `scripts/homebrew-core-formula.py` from the source archive
GitHub serves for the tag.

## What is already in place

| homebrew-core expects | Where it is met |
| --- | --- |
| a stable, tagged, checksummed source archive, never a branch | `url` is `archive/refs/tags/vX.Y.Z.tar.gz` with its sha256, written by `release-build.yml` once the tag exists |
| a build from source, nothing prebuilt downloaded | `cargo install --no-default-features --features model2vec`: the default `fastembed` feature downloads a prebuilt ONNX Runtime while building and vendors OpenSSL; `model2vec` is pure Rust, with no OpenSSL, ONNX or native TLS in its dependency tree |
| no self-updating software | the formula builds with `PIXEL_UPDATE_CHECK=off`: that binary never checks for a release, never prints the notice and never offers to upgrade itself (`update_notice.rs`); `pixel self-update` already refuses a binary Homebrew owns |
| a DFSG-compatible licence | MIT (`LICENSE`, `license "MIT"`) |
| a test that exercises the software | `brew test` indexes a Python file and searches it, offline, with `PIXEL_DAEMON_AUTO_START=0` so no daemon outlives the test |
| no manual install steps, nothing written outside the keg | no caveats, no `post_install`; `pixel install` (agent wiring in the user's home) is documented as the user's own step |
| `brew style`, `brew audit --strict --new` clean | `.github/workflows/homebrew-core.yml` builds the formula from a `git archive` of the tree on macOS and Linux, runs `brew test`, `brew linkage --test`, `brew style` and `brew audit --strict --new`, on every change to its inputs and weekly |
| `livecheck` and `head` | both declared |
| a free name | `pixel` is neither a formula nor a cask (formulae.brew.sh API, 2026-09-30) |

No external telemetry: metrics are local (`ARCHITECTURE.md`, "Invocation
accounting"). The network is reached only by features the user configures
(remote `decide` models, index download) and by the release check, which the
homebrew-core build removes.

## What no code change can meet: notability

`brew audit --new --online` refuses a GitHub repository with fewer than
**30 forks, 30 watchers and 75 stars** (all three below), or younger than 30
days. A **self-submission** (the formula's author opens the pull request)
triples the thresholds: **90 forks, 90 watchers or 225 stars**. Source:
`Library/Homebrew/utils/shared_audits.rb` (`GITHUB_NOTABILITY_THRESHOLDS`,
`SELF_SUBMISSION_THRESHOLD_MULTIPLIER = 3`).

On 2026-09-30 the repository has 24 stars, 1 fork and 0 watchers, and is 31
days old. Check before submitting:

```bash
gh repo view Pixel-CLI/pixel --json stargazerCount,forkCount,watchers \
  --jq '{stars: .stargazerCount, forks: .forkCount, watchers: .watchers.totalCount}'
```

Submit when one threshold is met: 75 stars (or 30 forks, or 30 watchers) for a
user who is not the author, 225 (or 90, or 90) otherwise. Before that, the
audit fails and the pull request is closed.

## Submitting

With the latest release's `pixel-core.rb`:

```bash
gh release download vX.Y.Z --repo Pixel-CLI/pixel --pattern pixel-core.rb
brew tap homebrew/core --force        # a local clone of homebrew-core to edit
cp pixel-core.rb "$(brew --repository homebrew/core)/Formula/p/pixel.rb"
HOMEBREW_NO_INSTALL_FROM_API=1 brew install --build-from-source pixel
brew test pixel
brew audit --new --strict --online pixel   # includes the notability check
brew style pixel
```

Then open the pull request on `Homebrew/homebrew-core`, titled
`pixel X.Y.Z (new formula)`, and fill its checklist. Say in the description:

- what pixel is, in one sentence, and why it is a formula (a CLI, no GUI);
- why `--no-default-features --features model2vec` (the default feature
  downloads a prebuilt ONNX Runtime at build time);
- that the build disables the release check (`PIXEL_UPDATE_CHECK=off`) so
  Homebrew owns updates;
- that `brew test` runs offline and leaves no process behind.

## After acceptance

- Point the tap at core: add `{"pixel": "homebrew/core"}` to
  `tap_migrations.json` in `LivioGama/homebrew-tap` and remove its
  `Formula/pixel.rb`, so `brew upgrade` moves tap users over.
- Stop the tap push in `release.yml` (the "Publish formula to the tap" step).
  Each release then needs a version bump on homebrew-core:
  `brew bump-formula-pr pixel --url <tag archive URL>`, unless Homebrew's
  autobump already covers the formula.
- Update the README install line to `brew install pixel`.
