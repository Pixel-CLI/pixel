**evidence brief:** a prompt that only weakly looks like it is about code (a code word or a question opener, but no identifier, path or backticked name) now runs a bounded `pixel classify` — the task-intent labels plus `none`, on whatever engine is configured — before the brief decides. A confident `none` verdict silences the brief (`ops` only steers — a measured `bugfix → ops` confusion must not deny evidence); `bugfix`, `refactor` or `review` verdicts run `impact` where the stem table would have missed it; the verdict renders as `intent: <label>`. The child is capped at 400 ms inside the existing 750 ms window and killed on timeout; classify off, a failing engine or an unconfident deny all fall back to the heuristic plan. Strong prompts never pay the call. `PIXEL_BRIEF_DEBUG=1` prints the verdict or the decline reason.
